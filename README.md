# VIR Registry

[简体中文](README.zh-cn.md) | English

The community index of voice packs for the VIR Signals editor extension.

## What this repository is

- One JSON file under `packs/` describes exactly one voice pack. The filename is the pack id.
- `registry.json` is the merged index served to every client. It is generated by `aggregate.js` and is never edited by hand.
- **This repository never stores audio.** A pack entry only points to the author's own repository at an immutable commit. Users download one pack from one author repository — never a bulk download of everything.
- If this registry ever goes away, the direct-install path (typing an author repository address) keeps working.

## For users

You do not need this repository directly. Install the VIR Signals extension, run **VIR: Select Voice Pack**, and the pack list shown there comes from this index. Picking an entry downloads that pack from its author repository.

## For authors

Publishing a pack means adding one JSON file here. See [CONTRIBUTING.md](CONTRIBUTING.md) for the full submission flow, the entry fields, and the twelve classes of broken entries that CI rejects.

## Layout

| Path | Role |
|---|---|
| `packs/` | Source entries, one file per pack, filename = pack id |
| `registry.json` | Generated index, `{"schema":1,"packs":[...]}` |
| `validate.js` | Entry validator (zero dependencies) |
| `aggregate.js` | Deterministic aggregator that builds `registry.json` |
| `test/run-tests.js` | Test suite |
| `template.json` | Copy-paste starting point for a new entry |
| `.github/workflows/registry.yml` | CI triple gate on pull requests |

## Scripts

All commands are plain Node with zero dependencies — no `npm install` needed.

```sh
node validate.js          # validate all entries + registry.json consistency
node aggregate.js         # rebuild registry.json from packs/
node test/run-tests.js    # run the test suite, report under reports/
```
